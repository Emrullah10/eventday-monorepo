# everyday — monorepo

EventDay backend + frontend as a Tropiq-style monorepo. See
`core/service-*/CLAUDE.md`-equivalent context below; each service/app also
documents its own conventions inline (`everyday-web-app/CLAUDE.md`).

## Layout
- `core/service-{identity,event,booking,aggregator}/` — framework-free domain logic (domain/application/infrastructure/interfaces), `make*` factory functions, no classes
- `services/everyday-service-{identity,event,booking,aggregator}/` — runnable shells (`main.js` → `src/boot.js` → `src/container.js`), one per core service
- `services/everyday-web-gateway/` — the only service with auth/JWT/cookies/CSRF/rate-limiting; downstream services trust its `x-user-id`/`x-user-role` headers, never re-verify JWTs
- `packages/modules/*` — shared npm packages (`@everyday/config`, `@everyday/datasource`, `@everyday/errors`, `@everyday/helper`, `@everyday/middlewares`, `@everyday/service-discovery`)
- `db-schemas/` — numbered domain SQL files + `combined-schema.sql` (generated by `scripts/build-schema.js`) + `migrations/`
- `everyday-web-app/` — React 19 + Vite frontend (see its own `CLAUDE.md`)
- `.wolf/` — AI session memory (minimum install: no hooks, instruction-based — see `.wolf/OPENWOLF.md`)

## Commands
- `npm install` (root — resolves all workspaces)
- `npm run build:schema` — regenerate `db-schemas/combined-schema.sql`
- Per service: `npm run dev -w services/<name>` (nodemon) or `npm run start -w services/<name>`
- Frontend: `npm run dev -w everyday-web-app`
- Tests: `npm test -w core/<service-name>` (Jest, per core package)

## Local ports
Gateway 5000 · identity 5001 · event 5002 · booking 5003 · aggregator 5004 · web-app 5173

## Running locally
Requires Postgres (apply `db-schemas/combined-schema.sql`) and Redis
(service discovery). Copy each service's `.env.example` to `.env`. Start all
five backend services, then the web app.
